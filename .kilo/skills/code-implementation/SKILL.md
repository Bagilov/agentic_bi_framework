# Реализация кода в agentic_bi_framework

Скилл — процедура внутри этого репозитория. Правила `AGENTS.md` воркспейса старше; здесь
порядок действий, реальные команды и грабли, проверенные на этом коде. Своего `AGENTS.md`
в репозитории нет — файл лежит на уровень выше, в корне воркспейса (`../AGENTS.md`).

Репозиторий: вложенный git-репо (`git -C <repo> rev-parse --show-toplevel` вернёт
`.../MyCode/agentic_bi_framework`), `.git` — файл (`gitdir: ../.git/modules/...`).
Git-команды — из каталога репозитория, не из корня воркспейса.

## 1. Карта кода

Пути модулей ниже — относительно `src/agentic_bi/`, если не указано иное.

| Что | Где |
|---|---|
| Пакет | `src/agentic_bi/` (`py.typed`, stdlib-only ядро) |
| Тесты | `tests/test_<module>*.py`, `testpaths = ["tests"]`, `pythonpath = ["."]` |
| Спека и API | `docs/IMPLEMENTATION.md` (разделы по подсистемам, §21 — known zones) |
| Обзор и команды | `README.md` |
| Примеры входа | `examples/*.json`, `examples/design_example.json` |
| Сборка `.pbix` | `engine/`, `_engine_build.ps1`, `_engine_oracle.py` |
| Гость Windows | `guest_*.py`, `desktop_oracle_guest.py` |
| Линейдж | `lineage/` (`SourceMixin`, `PlantUmlMixin`, `lineage_state.py`) |
| Конструктор | `constructor/` (`Design` → `Constructor` → отчёт) |
| Отчёты/PDF/web | `report/`, `web_report/`, `reportserver/` |

Подсистема из 2–5 файлов: читайте `__init__.py` (публичный API) и соседей по каталогу,
только потом правьте.

## 2. Окружение и гейты

В репозитории свой `.venv` (Python 3.12): `python`, `pytest`, `mypy`. `ruff` берётся из
воркспейса. Из каталога репозитория:

```bash
../.venv/bin/ruff check .                      # select = E,F,W,I,UP,B,BLE,RUF100; E501 ignored
../.venv/bin/ruff format --check .             # other/qwen-review исключён
.venv/bin/mypy                                 # = `mypy src` (files задан в pyproject), как в CI
find src tests -name __pycache__ -prune -exec rm -rf {} +
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B -m pytest -p no:cacheprovider \
    --cov=agentic_bi --cov-report=term
```

Приёмка — по строке успеха и порогу, а не по абсолютным числам (они меняются каждый коммит):

| гейт | признак успеха |
|---|---|
| `ruff check .` | `All checks passed!` |
| `ruff format --check .` | `N files already formatted`, без `Would reformat` |
| `mypy` | `Success: no issues found in N source files` |
| `pytest --cov=agentic_bi` | `N passed, M skipped` без `failed`/`error`, `Required test coverage of 72.0% reached` |

Перед сдачей сверяйтесь с `.github/workflows/ci.yml`: набор команд там тот же
(`ruff check .`, `ruff format --check .`, `mypy`, `pytest --cov=agentic_bi`), но пакет
ставится как `.[all,dev]` — см. правило про объявленные зависимости ниже.

`fail_under = 72` в `pyproject.toml` — это ratchet: пол поднимают только в том же
изменении, где добавлены тесты, и никогда не опускают.

Флаги `-B`, `PYTHONDONTWRITEBYTECODE=1`, `-p no:cacheprovider` обязательны: `__pycache__`
и `.pytest_cache` засоряют дерево и ломают `git status` и последующие прогоны.

## 3. Соглашения проекта (нарушение = не сдача)

- **Размер файла 25–300 строк** кода без пустых строк и комментариев. Крупнее — делить по
  ответственности; исключение помечается сверху `# Size exception (>300 lines): <причина>`.
- **Типы обязательны**: параметры, возвраты, поля. `Any` не используется; любое
  подавление (`# type: ignore`, глушащий `cast`) допустимо только с причиной в комментарии.
- **Граница**: недоверенный вход (JSON/YAML spec, `.pbix`, HTTP, файл, layout) проверяется
  до использования и превращается во внутренний тип. Отказ границы — `ValueError`/`OSError`,
  не `KeyError`/`AttributeError`/`TypeError` из середины.
- **Exit-коды CLI**: `0` успех, `1` отработал и результат отрицательный, `2` плохой вход.
  Тело оборачивается в `cli_support.run_boundary`; `_INPUT_ERRORS` уже включает
  `zipfile.BadZipFile`, поэтому новый тип ошибки входа добавляется туда и в общий тест
  UX, а не в `try/except` каждой команды.
- **Опциональные зависимости деградируют**: отсутствие `pyarrow`/`xpress9`/`pywinrm`/
  `pbixray` — не падение импорта пакета, а явный отказ функции.
- **Логирование, не печать**: библиотечный код пишет `logger`, CLI — в stdout/stderr.
  Осознанный `except Exception` — только с `# noqa: BLE001` и причиной (это проверяет `BLE`).
- **Known zones** (`docs/IMPLEMENTATION.md` §21): внешняя БД портала, Oracle-источники,
  внутренности Power BI Desktop, донорская VertiPaq-модель. Такое место помечается в
  docstring (что известно / что непрозрачно / от чего зависит), детали не парсятся и не
  печатаются, при недоступности возвращается `unresolved`/`SKIPPED` с причиной — не выдуманное
  значение и не тихий успех.
- **Секреты** — только `os.getenv()`/`load_dotenv()`; значения не логируются, не хардкодятся
  и не попадают в фикстуры. Воркспейсный `pre-commit` установлен, но в этом репозитории
  `.env` нет, поэтому его проверка секретов **пропускается** («no .env found … the .env
  secret check is SKIPPED») — то есть на хук здесь рассчитывать нельзя, секреты ловятся
  только ревью. Тесты используют плейсхолдеры (`user="u"`, `password="p"`), не реальные
  значения.
- Внешние данные из корпоративных источников обезличиваются: env-переменные
  (`PBI_RS_BIN`, `PBI_RS_DESKTOP`, `PBI_RS_TEMPLATE`, `AGENTIC_BI_GUEST_*`) и аргументы CLI
  вместо путей/домён/имён схем.
- **Только объявленные зависимости**: CI ставит `.[all,dev]`, поэтому импорт пакета,
  которого нет в `pyproject.toml`, зелёный локально и красный в CI. Локальный `.venv`
  содержит и необъявленные пакеты (например `pypdfium2 5.13.0` и `pypdf 6.19.0` — в
  `pyproject.toml` их нет, в `src` и `tests` они не импортируются). Новая зависимость
  объявляется в extras и появляется в CI тем же изменением; для разовой проверки PDF —
  `pytest.importorskip`, а не голый `import`.
- **Новая команда CLI**: entry point регистрируется в `pyproject.toml` `[project.scripts]`,
  но в текущем `.venv/bin` он не появится до переустановки пакета. До этого запускайте
  `python -m agentic_bi.<module>`; тест импортирует `main()` напрямую, а не консольный
  скрипт (пример: `tests/test_constructor_cli.py`).
- **Новый runtime-файл** (`.ps1`, конфиг, шаблон), который читается из пакета, добавляется в
  `[tool.setuptools.package-data]`, иначе он не попадёт в wheel и тест на чистой установке
  упадёт.
- Публичный API меняется — `README.md` и `docs/IMPLEMENTATION.md` правятся в том же
  изменении, что и код.

## 4. Порядок работы

### Шаг 1. Осмотреться

```bash
git -C <repo> status --short && git -C <repo> diff --stat
git -C <repo> log --oneline -5
```

Читать существующие тесты модуля: тест — контракт. Если он противоречит задумке, меняется
вместе с кодом и это видно в диффе.

### Шаг 2. Материализовать

Код сначала в файл (`write`/`edit`), потом сообщение о нём. Код в ответе без записи —
ошибка. Одноразовая проверка — отдельный файл с явным именем (`test_<module>_<case>.py`,
`<module>_scratch.py`), а не `if __name__ == "__main__"` в рабочем модуле. Временные
файлы — `_to_delete/` (каталог создаётся при необходимости) или
`other/<experiment>/README.md`; scratch-каталог брать из `$TMPDIR` и создавать до
использования: `mkdir -p "$TMPDIR/kilo"`.

Мёртвый и закомментированный код удаляется. `vulture` в `.venv` **не установлен** —
перед использованием проверить `command -v vulture`; если его нет, искать мёртвое через
`git grep -n "def <name>" src tests` и точечный обзор диффа, а не выдумывать прогон.

### Шаг 3. Тесты

Тест обязателен на новую функцию, модуль и исправленный баг. Покрывать happy path,
границы (пусто/ноль/максимум) и отказ. Имя — про поведение:
`test_returns_error_when_token_expired`.

Детерминизм: `tmp_path`, моки, фикстуры. Никакой сети, реального гостя, Desktop или
`/tmp/...` в пути. Платформенный тест (Windows-гость, браузер, Desktop) гейтится
env-переменной и скипается — пример: `tests/test_pbix_desktop_oracle.py` требует
`AGENTIC_BI_GUEST_*` и `xpress9`.

Mutation-check — доказательство, что тест ловит именно правку:

```bash
shasum -a 256 src/agentic_bi/<file>.py        # зафиксировать
# откатить правку (или внести, если тест писался первым)
.venv/bin/python -B -m pytest -p no:cacheprovider -q tests/test_<module>_<case>.py
# ожидается падение; восстановить файл и сверить shasum -a 256
```

`sha256sum` есть по пути `/sbin/sha256sum`; `shasum -a 256` — то же без пути.

### Шаг 4. Гейты

Порядок дешёвое → дорогое, красный гейт запрещает сдачу (команды в §2). Отдельно:
`--cov` без значения берёт `source` из `pyproject.toml`, но в связке с `--collect-only`
падает на floor — покрытие меряется только полным прогоном.

### Шаг 5. Обезличивание (порт из другого репозитория)

Переносится механика, не идентичность. Deny-список держите **вне репозитория**
(`"$TMPDIR/kilo/denylist.txt"`, по токену на строку: домены, схемы/таблицы внутренних БД,
логины, коды тикетов, названия подразделений, корпоративные hex-палитры) — файл внутри репо
сам стал бы следом и совпал бы с собственным поиском. Проверяются источник, рабочее дерево,
история и сообщения коммитов:

```bash
L="$TMPDIR/kilo/denylist.txt"
git grep -nFf "$L" HEAD                                          # 1 = совпадений нет (успех)
git ls-files -o --exclude-standard -z | xargs -0 grep -nIFf "$L" # 1 = чисто; пустой список untracked безопасен
git log --format="%s%n%b" origin/main..HEAD | grep -niFf "$L"     # 1 = чисто
grep -railF -f "$L" templates output_files                        # артефакты и бинарники; 1 = чисто
```

Во всех четырёх командах `exit 1` — это «чисто», а не ошибка: не превращайте его в падение
шага. Каталоги передавайте без `/*`: глоб с подкаталогами даёт `Is a directory` и `exit 2`,
который легко принять за находку. Несуществующий каталог в аргументах (например
`output_files` после чистки) тоже даёт `exit 2` — уберите его из команды.
`git grep --untracked` не поддерживается (exit 128) — untracked-файлы сканируются
отдельной командой выше.

Отрицательный результат проверяйте положительным контролем: положите в отдельный список
строку, которая точно есть в проверяемом дереве (имя члена контейнера, имя класса), и
убедитесь, что сканер её находит. Без контроля `exit 1` одинаково означает и «чисто», и
«опечатка в пути». Ищите и латиницу, и кириллицу: список должен содержать оба написания.

### Шаг 6. Коммит

Только по явному запросу. Один коммит — одно логическое изменение и один репозиторий.

- Формат `<type>(<scope>): <description>`, типы `feat|fix|refactor|chore|docs|test|style|perf|ci|build|revert`.
- Сообщение на английском; тело — почему и каким измерением подтверждено.
- Stage только нужные файлы; `.env` и секреты не коммитить; хуки не обходить
  (`--no-verify` — только осознанный инцидент и отдельный коммит с исправлением).
- `post-commit` пушит по политике `HOOK_AUTOPUSH`, поэтому коммит без пуша —
  `HOOK_AUTOPUSH=0 git commit -m "..."`.
- Пуш — только по запросу. Если HTTPS отклонён политикой токена (коммит трогает
  `.github/workflows/`), а SSH-ключ настроен — пуш по SSH; remote не переписывается,
  force-push не используется.

## 5. Грабли, проверенные на этом коде

- **Правка источника, а не вызова**: каталог в `Popen` даёт `PermissionError: [WinError 5]`,
  поэтому путь нормализуется (`desktop_bin`/`desktop_exe`), а не оборачивается `try/except`
  у вызывающего.
- **Устаревший артефакт маскирует падение**: выходной `.abf`/`.pbix` удаляется перед
  прогоном, иначе прошлый успех читается как текущий.
- **PowerShell 5.1**: `[IO.File]::Move(a,b,$true)` не существует; `Remove-Item` по
  несуществующему пути под `Stop` даёт exit 1; `-Path` — wildcard, `-LiteralPath` —
  литерал; скрипт без BOM читается в системной ANSI-кодировке, поэтому не-ASCII литералы
  в `.ps1` ломаются (текущий `_engine_build.ps1` — чистый ASCII, поэтому работает без BOM;
  добавление кириллицы требует BOM); `New-Object -ComObject '<GUID>'` трактует аргумент
  как ProgID (нужен `[Type]::GetTypeFromCLSID` + `[Activator]::CreateInstance`).
- **Сравнение по подстроке вместо структуры**: `"In"` в сериализованном JSON ловит
  `Include/Income/Index`; фильтр разбирается как объект.
- **Захардкоженный путь в тесте** (`/tmp/...`, `C:\pbi\...`) падает на чистой машине —
  `tmp_path` или env.
- **Титул визуала** живёт в `singleVisual.vcObjects.title`, а не `objects.title`.
- **`pypdfium2`/`pypdf`** есть в локальном `.venv`, но не объявлены в `pyproject.toml` —
  импорт в тесте пройдёт у вас и упадёт в CI; для PDF-проверок `pytest.importorskip`.

## 6. Чек-лист сдачи

1. Размер файлов в норме, исключения обоснованы.
2. Типы явные; подавлений нет или они объяснены.
3. Вход проверен на границе; отказ — типизированное исключение и правильный exit-код.
4. Тесты на новое/исправленное написаны; mutation-check подтверждён.
5. `ruff check`, `ruff format --check`, `mypy`, полный `pytest --cov` — пройдены
   фактически, вывод есть.
6. Корпоративных следов нет ни в коде, ни в сообщениях коммитов.
7. Код материализован в файлы; одноразовые проверки не остались в рабочем модуле.
8. Коммит/пуш — только если попросили; затронутые репозитории названы.

## 7. Если меняется правило

Скилл — производная от `pyproject.toml`, `AGENTS.md` и хуков, а не второй источник истины.
Меняли гейт, порог покрытия, набор ошибок входа или политику коммитов — обновите этот файл
тем же заходом.
