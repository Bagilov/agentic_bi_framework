# Ревью: OpenSpec + код — stage0-hardening-and-guest-chain

Ты — независимый ревьюер. К промпту приложены **файлы**: спецификации OpenSpec и
исходный код на Python, который их реализует.

## Что за изменение

Репозиторий `agentic_bi_framework` (пакет `agentic_bi`, stdlib-only ядро).
Изменение закрывает 4 дефекта (2 из них — исполнение внешних данных как кода) и
добавляет сквозную «guest-цепочку» сборки тестового дашборда в Windows-VM.

ВАЖНО: чат принимает не более ~5 вложений, поэтому материалы собраны в **3
бандла** (каждый бандл — markdown, где секции разделены строкой
`==================== FILE: <путь> ====================`). Читай код **из бандлов**,
а не из отдельных файлов; отдельные файлы могут быть недоступны.

- `round5-openspec-bundle.md` — вся OpenSpec: `proposal.md`, `design.md`,
  `tasks.md`, `specs/…/spec.md`
- `round5-code-a-guest.md` — guest-цепочка: `guest_types`, `guest_vm`,
  `guest_winrm`, `guest_staging`, `guest_task`, `guest_transport`,
  `guest_chain_build`, `guest_chain`, `guest_chain_cli`
- `round5-code-b-graph.md` — бинарный слой и web-report: `pbix_binary/patch_pipeline`,
  `pbix_binary/abf_model`, `web_report/web_render`, `web_report/web_assets`

Если каких-то файлов всё равно не видно — так и напиши, какие именно.

## Что вернуть

1. **Соответствие спеки коду.** Для каждого BR-1..BR-7: реализован ли он в
   приложенном коде? Если нет — назови BR и что не сходится. Если сценарий из
   `openspec-spec.md` невыполним при текущем коде — назови сценарий.
2. **Дыры в спеке.** Какие требования/сценарии отсутствуют, хотя нужны для
   полноты (границы, ошибки, безопасность)? Приведи конкретные scenario-блоки,
   которые стоит добавить.
3. **Дефекты кода.** Только высокоуверенные: что реально сломается у
   пользователя. По каждому — файл, функция, условие срабатывания, severity
   (critical/warning/nit).
4. **Противоречия.** Где спека обещает одно, а код делает другое.

Не пересказывай код. Только конкретика: BR/сценарий/файл:функция + условие.
Если по пункту нет замечаний — так и напиши «нет замечаний».
