# Ревью: сборка дашборда (board/spec/skeleton) и агенты

Ты — независимый ревьюер Python-кода. К промпту приложены **файлы** (3 бандла).

ВАЖНО: чат принимает не более ~5 вложений, поэтому код собран в 2 бандла — это
markdown, где секции разделены строкой
`==================== FILE: <путь> ====================`. Читай код из бандлов:
- `round11-code-a-core.md` — `board.py`, `spec.py`, `engine_layout_visual.py`,
  `engine_layout_query.py`, `engine_types.py`, `skeleton.py`,
  `skeleton_assembly.py`, `board_fake.py`
- `round11-code-b-rest.md` — `skeleton_visuals.py`, `skeleton_visuals_extra.py`,
  `build.py`, `agents.py`, `inspect_board.py`, `dax_markers.py`

## Что за код

Пакет `agentic_bi` (stdlib-only ядро) собирает дашборд Power BI.

1. **Модель доски** (`board.py`, `spec.py`, `engine_types.py`): декларативная
   `DashboardSpec` (страницы/элементы/позиции/поля) проверяется и превращается в
   `Board`; затем `board.py` рендерит объекты layout Power BI (`visualContainers`,
   `singleVisual`, `projections`, `prototypeQuery`).
2. **Layout-фрагменты** (`engine_layout_visual.py`, `engine_layout_query.py`):
   построение одного визуала и его query (`From`/`Select`, роли проекций) по типу
   визуала и полям.
3. **Скелет** (`skeleton*.py`, `board_fake.py`, `build.py`): генерация готового
   PBIP-скелета (KPI + график + таблица + фильтры) и «склейка» layout в бинарный
   `.pbix`; `build.py` — высокоуровневая сборка.
4. **Агенты/инспекция** (`agents.py`, `inspect_board.py`, `dax_markers.py`):
   манифест агентов (валидация на границе), статическая инспекция готового
   layout, маркеры DAX.

Контекст: вход — **декларативная спека и имена** (поля/таблицы/меры), которые
могут прийти от пользователя/из конфига. Имена попадают в JSON layout и в
Power BI query. Это сборка «с нуля», а не аудит: ошибка здесь означает, что
`.pbix` откроется пустым, с битым визуалом или с неверной привязкой.

## Что вернуть

1. **Корректность layout.** Может ли `board.py` / `engine_layout_*` собрать
   объект, который Power BI не откроет или откроет пустым: пустые `projections`,
   дубликат id/позиции, роль без полей, `From` без `Select`, несогласованные
   `queryRef`/`prototypeQuery`, отсутствующий `visualType`? Файл:функция + условие.
2. **Границы спеки.** Где некорректная/неполная спека даёт `KeyError`/
   `IndexError`/`TypeError` вместо понятной ошибки: элемент без `pos`, дубликат
   имени страницы, неизвестный `kind`, пустой список полей, `None` вместо
   строки? Что проверяет `spec.validate_spec`, а что доходит до рендера?
3. **Экранирование имён.** Имена полей/таблиц/заголовков попадают в JSON и в
   query: возможен ли сломанный JSON, неэкранированная кавычка в `queryRef`,
   инъекция в DAX-выражение (`prototypeQuery`/`Select`), пустое/пробельное имя?
4. **Скелет и сборка.** Ошибки позиций (наложения, отрицательные размеры, выход
   за холст), потеря фильтров/мер, `board_fake` расходится с реальным `board`,
   `build.py` молча пропускает шаг.
5. **Дефекты.** Только высокоуверенные: что реально сломается или соврёт.
   Границы: одна страница, один визуал, 0 полей, юникод в имени, дубликат id.

По каждому — файл:функция, условие, severity (critical/warning/nit). Если по
пункту нет замечаний — «нет замечаний». Не пересказывай код.
