# Ревью: декларативный spec-путь (spec → layout → validate → web)

Ты — независимый ревьюер Python-кода. К промпту приложены **файлы** (3 бандла).

ВАЖНО: чат принимает не более ~5 вложений, поэтому код собран в 3 бандла — это
markdown, где секции разделены строкой
`==================== FILE: <путь> ====================`. Читай код из бандлов:
- `round7-code-1-spec-layout.md` — `spec.py`, `engine_layout.py`, `engine_layout_query.py`
- `round7-code-2-validate-thresholds.md` — `validate_pbix.py`, `thresholds.py`
- `round7-code-3-web.md` — `web_report/web_model.py`, `web_report/web_checks.py`,
  `web_report/web_inspect.py`

## Что за код

Пакет `agentic_bi` (stdlib-only ядро) собирает дашборд Power BI так:

1. **Декларативная спека** (`spec.py`): YAML/JSON → `DashboardSpec`
   (tables/columns/measures/pages/visuals/thresholds/support). Внешние данные,
   валидируются на границе.
2. **Спека → layout** (`engine_layout.py`): строится байтовый `Report/Layout`
   (JSON) из спеки; `engine_layout_query.py` — наборы queryRef/Select.
3. **Пороги** (`thresholds.py`): каталог порогов (severity/условие) с
   переопределением из спеки.
4. **Валидация** (`validate_pbix.py`): структурная проверка собранного `.pbix`
   против спеки (объекты модели, страницы, обязательные визуалы).
5. **Web-report** (`web_report/`): `web_model.py` строит модель из
   `Report/Layout` + реестра; `web_checks.py` — проверки (модель-члены, фильтры,
   условия); `web_inspect.py` — чтение реестра из `.pbix` через `pbixray`.

Контекст: `spec.py` — внешний вход (недоверенный); layout/query — вывод, который
должен быть валидным JSON и не исполнять данные как код; пороги и проверки влияют
на решение «публиковать или нет».

## Что вернуть

1. **Валидация границы.** Достаточно ли строго `spec.py` проверяет недоверенный
   ввод (типы, обязательные поля, диапазоны, дубликаты имён)? Где спек с
   неожиданным типом/значением приведёт к позднему `KeyError`/`TypeError` или к
   молчаливо неверному layout? Файл:функция + условие.
2. **Консистентность данных.** Может ли спека пройти валидацию, но дать layout,
   который потом не пройдёт `validate_pbix` (или наоборот)? Найди конкретные
   несоответствия между `engine_layout*`, `validate_pbix` и `web_model`.
3. **Пороги.** Корректен ли приоритет переопределений в `thresholds.py`
   (каталог vs спека)? Есть ли значение по умолчанию, которое тихо скрывает
   нарушение (fail-open)?
4. **Web-checks.** Есть ли проверка, которая молча проходит при отсутствии
   данных (пустой реестр, отсутствующий ключ) вместо «нет данных → предупреждение»?
5. **Дефекты.** Только высокоуверенные: что реально сломается или соврёт.

По каждому — файл:функция, условие, severity (critical/warning/nit). Если по
пункту нет замечаний — «нет замечаний». Не пересказывай код.
