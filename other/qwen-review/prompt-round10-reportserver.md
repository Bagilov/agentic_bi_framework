# Ревью: Report Server диагностика, антипаттерны DAX и автоматизация

Ты — независимый ревьюер Python-кода. К промпту приложены **файлы** (3 бандла).

ВАЖНО: чат принимает не более ~5 вложений, поэтому код собран в 3 бандла — это
markdown, где секции разделены строкой
`==================== FILE: <путь> ====================`. Читай код из бандлов:
- `round10-code-1-reportserver.md` — `reportserver/reportserver_client.py`,
  `reportserver/diagnostics.py`, `reportserver/pbix_analysis.py`,
  `reportserver/pbix_index.py`
- `round10-code-2-antipatterns.md` — `antipatterns/antipattern_registry.py`,
  `antipattern_detectors.py`, `pbi_antipatterns.py`, `dax_detail.py`
- `round10-code-3-automate.md` — `automate.py`, `cli_support.py`, `engine_cli.py`

## Что за код

Пакет `agentic_bi` (stdlib-only ядро, опциональные extras).

1. **Report Server** (`reportserver/`): обход каталога Power BI Report Server по
   OData REST API v2.0 с аутентификацией Negotiate (spnego), диагностика
   подписок/расписаний, анализ `.pbix`-архивов, индексация. Сеть, хосты,
   таймауты, пагинация, пути (`Path` из имён сервера).
2. **Антипаттерны DAX / детализация** (`antipatterns/`, `dax_detail.py`): реестр
   правил и детекторы по тексту DAX/мер; разбор DAX-выражений и отчёт деталей.
   Вход — **недоверенный** текст (имена мер, выражения из модели).
3. **Автоматизация** (`automate.py`) и **граница CLI** (`cli_support.py`,
   `engine_cli.py`): оркестрация шагов, единая обработка ошибок и коды выхода.

Контекст: это инструмент аудита чужих отчётов. Он ходит по сети (Report Server),
читает имена/пути из чужого каталога и разбирает чужой текст DAX. Диагностика не
должна падать на неожиданном ответе сервера и не должна молча выдавать «чисто».

## Что вернуть

1. **Небезопасная работа с сетью/ответом.** Где код доверяет форме ответа
   сервера (`_value`, JSON-поля, `@odata.nextLink`, пагинация, статусы,
   редиректы, таймауты, `verify=False`)? Что будет при отсутствующем поле,
   не-JSON теле, `None` вместо списка? Файл:функция + условие.
2. **Пути и имена.** Может ли имя/путь из сервера (`Path`, склейка имени файла,
   `output_dir`, `_sanitize`) выйти за пределы каталога или создать опасное имя
   (обход каталога, абсолютный путь, `..`, пустое имя, разделитель)?
3. **Детекторы антипаттернов.** Ложные срабатывания/пропуски: регистр, пробелы,
   комментарии, вложенные функции, регулярные выражения (катастрофический
   бэктрекинг), пустой DAX. Есть ли правило, которое тихо не сработает?
4. **Граница CLI и автоматизация.** Правильны ли коды выхода и обработка
   исключений (`cli_support.run_boundary`)? Может ли ошибка быть проглочена и
   вернуть «успех»? Согласованы ли шаги `automate.py` с реальными именами
   функций/модулей (нет ли вызова отсутствующего API)?
5. **Дефекты.** Только высокоуверенные: что реально сломается или соврёт.
   Границы: пустой ответ, один элемент, отсутствующий ключ, юникод в имени,
   очень большое имя/путь.

По каждому — файл:функция, условие, severity (critical/warning/nit). Если по
пункту нет замечаний — «нет замечаний». Не пересказывай код.
