# Proposal: stage0-hardening-and-guest-chain

> Источник: запросы пользователя — «продолжи сессию agentic_bi_framework»,
> «проведи настоящий тест», «реализуй», «проведи ревью с квеном по каждому
> сервису — пользовательскому пути и агентскому тоже».

## Why

Фреймворк `agentic_bi` умеет собирать и проверять `.pbix`, но при независимом
ревью (Qwen, 4 раунда) выяснилось: часть путей **заявляет успех, а на диск пишет
битый артефакт**, часть **исполняет внешние данные как код**, а сквозного пути
«создай тестовый дашборд одной командой» не было вообще — сборка в Windows-VM
делалась руками через интерактивную scheduled task.

Конкретно:

- `web_report` вставлял JSON в `<script>` без экранирования `<`/`>` — заголовок
  визуала вида `</script><script>…</script>` исполнялся в браузере (воспроизведено);
- ключ элемента попадал в JS-строку внутри `onclick` — имя страницы с `'`
  ломало строку и исполнялось по клику (воспроизведено);
- `serialize_virtual_directory` собирал XML f-строками без экранирования, а
  парсер декодирует сущности: путь с `&` давал `.pbix`, чей `DataModel` не
  читается, при `apply_patches == успех`;
- equal-length патч, совпавший в нескольких местах, молча правил первое;
- цепочки «VM → сборка → pull → Desktop-оракул → teardown» не существовало;
- ошибки границ (CLI-вход, манифест агента) не валидировались и отдавали
  стектрейсы вместо контракта.

## What Changes

- **BR-1: Нет исполнения данных как кода в web-report.** Сгенерированный HTML
  SHALL экранировать потенциально опасные символы в любом сериализованном
  payload и SHALL не строить JavaScript внутри HTML-атрибутов.
- **BR-2: Записанный `.pbix` всегда читаем.** `apply_patches` SHALL
  сериализовать virtual directory корректно (экранирование) и SHALL
  перечитывать и переразбирать результат перед возвратом; при неудаче — ошибка.
- **BR-3: Неоднозначный патч не применяется молча.** Патч, совпавший более
  одного раза, SHALL завершаться ошибкой, если явно не задан `occurrence`
  (0-based индекс) или `"occurrence": "all"`.
- **BR-4: Сборка тестового дашборда — одна ограниченная команда.** Система SHALL
  иметь один вызываемый путь, который поднимает VM, стейджит фреймворк, собирает
  дашборд в интерактивной сессии, забирает `.pbix` на хост, опционально гоняет
  Desktop-оракул и всегда убирает за собой, завершаясь ровно одним вердиктом.
- **BR-5: Стейджинг не отдаёт лишнего.** Хост-сервер для передачи файлов в гость
  SHALL отдавать только один файл по одноразовому токену и SHALL проверять
  целостность переданного файла.
- **BR-6: Никакой интерполяции в PowerShell без экранирования.** Любое значение,
  попадающее в PowerShell-скрипт, SHALL проходить через единый помощник
  экранирования.
- **BR-7: Границы валидируются.** Консольные точки входа SHALL возвращать
  документированный код на плохой вход (без стектрейса), а манифест агента SHALL
  отвергать неизвестный `stage`.

## Impact

- **Затронутые спеки:** `web-report-rendering`, `pbix-binary-patching`,
  `guest-chain`, `cli-contract`, `agent-manifest`.
- **Компоненты:** `web_report/web_render.py`, `web_report/web_assets.py`,
  `pbix_binary/abf_model.py`, `pbix_binary/patch_pipeline.py`,
  `pbix_binary/patch_cli.py`, новый пакет `guest_*` (9 модулей),
  `desktop_oracle_guest.py`, `engine.py`, `engine_host.py`, `_engine_build.ps1`,
  `pyproject.toml`, тесты.
- **Расписание/триггеры:** CLI по запросу; guest-цепочка — по запросу на сборку
  тестового дашборда; оракул — опциональным флагом.
- **Ожидаемый объём:** дашборды — единицы; `.pbix` — до сотен МБ; VM (UTM,
  Windows 11 ARM) — одна.
- **Приоритет:** высокий (два дефекта — исполнение кода); BR-4/BR-5 — высокий.

## Non-Goals

- Валидация диапазонов offset/size из vdir (D-2) — вынесено в `0.0.2`.
- Замена WinRM/scheduled-task на прямой `msmdsrv.exe` — исследовательский вопрос,
  в бэклоге (по итогам раунда 2).
- `mypy --strict`, поднятие порога покрытия одним прыжком, lock-файл в артефакте —
  см. `docs/IMPROVEMENT_PLAN.md` §4.
- Реализация write-варианта `render_kilo_agent` (санитизация `agent.id`) — только
  при появлении такой функции.

# Design: stage0-hardening-and-guest-chain

## Context

`agentic_bi` — stdlib-only ядро (92 модуля, 11 консольных точек входа,
опциональные extras). Два способа получить `.pbix`:

1. **Донорский:** взять бинарный `DataModel` из образца и заменить только
   `Report/Layout` (`rebuild.py`), плюс байтовые правки ABF
   (`pbix_binary/`).
2. **Движковый:** собрать модель с нуля AS-движком Power BI Desktop, но движок
   живёт только на Windows и только в интерактивной сессии (session 1); на Apple
   Silicon Desktop нет, поэтому сборка шла через Windows-VM.

HTML-клон дашборда (`web_report/`) рендерит `Report/Layout` в одну страницу и
сериализует модель в `<script>` для интерактивности (тултипы, панель фильтров,
поповер деталей).

До изменения: сериализация была `json.dumps` без экранирования, клик — через
инлайновый `onclick` со вставкой ключа в JS-строку; serialization virtual
directory — ручные f-строки; метод равнодлинных байтовых патчей брал первое
совпадение; сборка в VM делалась вручную.

## Decisions

- **Экранирование в единственной точке стока.** `_json_for_script` заменяет
  `<`,`>`,`&` на `\u003c`/`\u003e`/`\u0026` на выходе сериализации, а не на
  каждом входе — тогда будущие источники покрыты автоматически, и JSON остаётся
  валидным. HTML-санитайзер **не** используется: он испортил бы легитимные
  `<`/`>` в подписях.
- **Клик без JS-in-HTML.** Ключ едет в `data-key`, обработчик вешается через
  `addEventListener`; в клиенте добавлен `escapeHtml` для строк, попадающих в
  `innerHTML`. Экранировать сильнее строку внутри `onclick` — неверный класс
  фикса.
- **Virtual directory — через `ElementTree`.** Проверено: для нормальных путей
  вывод байт-идентичен прежнему serializer'у, декларация XML не добавляется,
  экранирование корректно. Замена behaviour-preserving.
- **Self-verification после записи.** `apply_patches` перечитывает записанный
  `.pbix`, распаковывает `DataModel`, парсит ABF-индекс. Не опция — иначе прежний
  дефект снова доедет до диска. `zip.testzip()` проверяет архив, но не модель
  внутри.
- **Неоднозначность — ошибка.** `occurrence` (0-based) или `"all"`; иначе
  `PatchError`. Сканирование **не пересекающееся** (`start += len(find)`) и
  ленивое (`limit`), чтобы короткий повторяющийся паттерн не давал ложную
  неоднозначность и не строил миллионный список offset'ов.
- **Один `Deadline` на всю цепочку.** Каждый этап берёт срез оставшегося
  бюджета; teardown — в `finally`; VM останавливается только если её подняла эта
  цепочка (`started_vm`). Процесс завершается ровно одним вердиктом
  (`BUILT`/`NOT_BUILT`/`STAGE_FAILED`/`ORACLE_FAILED`/`TIMEOUT`).
- **Стейдж-сервер — один файл, токен, SHA-256.** Вместо `0.0.0.0` + выдача
  каталога: привязка к адресу гостя (с fallback и предупреждением), отдача
  строго одного файла по одноразовому токену, 404 на всё остальное, и гость
  сверяет SHA-256 — порча/усечение дают `StageError`.
- **Завершение задачи — маркер-файл, не строка в логе.** PowerShell `*>` пишет
  UTF-16, `Out-File -Encoding utf8` дописывает UTF-8 — текстовый сентинел
  приходит искажённым. Токен `EXITCODE=` живёт в одной константе.
- **`ps_quote` для всего, что попадает в PowerShell.** Значение оборачивается в
  одинарные кавычки с удвоением `'`; служебный `-Argument` scheduled task
  экранирует `"` для командной строки Windows.
- **Разбиение под правило 25–300 строк.** Транспорт и цепочка разрезаны по
  ответственности: `guest_types` (бюджет/ошибки/`ps_quote`/конфиг), `guest_vm`,
  `guest_winrm`, `guest_staging`, `guest_task`, `guest_transport` (композиция),
  `guest_chain_build`, `guest_chain` (вердикт), `guest_chain_cli`.

## Risks / Trade-offs

| Риск | Митигация | Ответственный | Срок |
|------|-----------|---------------|------|
| Mandatory self-verify замедляет большие модели (двойная распаковка) | Оставлено обязательным: миллисекунды против «успех + битый файл»; оптимизация — отдельно | Разработчик | 0.0.2 |
| Fallback стейджинга на `0.0.0.0`, если адрес не локальный | Печатается `warning`; доступ всё равно ограничен одноразовым токеном и одним файлом | Разработчик | сделано |
| Гостевые пути (`_pth`, root) зависят от конфига | Выводятся из `guest.python`/`guest.root`, не хардкодятся | Разработчик | сделано |
| WinRM cold-boot нестабилен (NTLM отваливается) | Retry с новой сессией + требование двух подряд успешных проб | Разработчик | сделано |
| PowerShell всё ещё собирается f-строками | Значения проходят `ps_quote`; переход на encoded-arguments — в бэклоге | Разработчик | 0.0.2 |

## Open Questions

- Оставить ли self-verify всегда включённым или дать `verify=True` по умолчанию
  с явным отказом для batch-кейсов (сейчас — всегда).
- Достаточно ли `data-key`+`addEventListener`, или перевести поповер деталей на
  `textContent` вместо `innerHTML` + `escapeHtml`.
- Нужен ли Windows CI-leg для guest-модулей (без Desktop) — см. план, этап 1.

# Spec: stage0-hardening-and-guest-chain

## ADDED Requirements

### Requirement: Экранирование payload в web-report
Генерируемый HTML SHALL экранировать символы `<`, `>`, `&` в любом
сериализованном payload, встраиваемом в `<script>`, и SHALL не размещать
JavaScript внутри HTML-атрибутов.

#### Scenario: Метка визуала содержит закрывающий тег script
- **GIVEN** в `Report/Layout` дашборда метка визуала содержит
  `</script><script>…</script>`
- **WHEN** дашборд рендерится в HTML и открывается в браузере
- **THEN** сгенерированная страница не содержит литерального `</script>` из
  payload, `document.title` остаётся исходным, скрипт не исполняется, а метка
  целиком возвращается через `JSON.parse`

#### Scenario: Ключ элемента содержит одинарную кавычку
- **GIVEN** имя страницы содержит `'`
- **WHEN** пользователь кликает по элементу в браузере
- **THEN** открывается поповер деталей, а инъецированный JS не исполняется
  (обработчик берёт ключ из `data-key`)

### Requirement: Читаемость записанного `.pbix`
`apply_patches` SHALL сериализовать virtual directory с корректным
экранированием и SHALL перечитывать и переразбирать записанный `DataModel`
перед возвратом; при неудаче SHALL возбуждать `PatchError`.

#### Scenario: Патч после пути с амперсандом
- **GIVEN** донорский vdir содержит путь с `&` (декодируется в символ `&`)
- **WHEN** через CLI применяется патч изменяемой длины
- **THEN** записанный `.pbix` содержит экранированный путь
  (`A&amp;B_Storage_1234`), `DataModel` парсится, путь round-trip'ится в `A&B_...`

#### Scenario: Будущий дефект writer'а
- **GIVEN** реализация writer'а такова, что записанный `DataModel` не парсится
- **WHEN** `apply_patches` завершает запись
- **THEN** self-verification возбуждает `PatchError`, а CLI возвращает код 2 и
  не заявляет успех

### Requirement: Неоднозначный байтовый патч отвергается
Equal-length патч, найденный более одного раза, SHALL завершаться ошибкой, если
явно не задан `occurrence` (0-based индекс) или `"occurrence": "all"`.

#### Scenario: Паттерн совпал в нескольких местах
- **GIVEN** `find` совпадает в 437 местах и `occurrence` не задан
- **WHEN** патч применяется
- **THEN** возникает `PatchError` с числом совпадений, файл не пишется, CLI
  возвращает код 2

#### Scenario: Явный выбор одного совпадения
- **GIVEN** тот же паттерн и `occurrence: 1`
- **WHEN** патч применяется
- **THEN** правится ровно второе совпадение, остальные не меняются

#### Scenario: Ложная неоднозначность отсутствует
- **GIVEN** паттерн не пересекается сам с собой и встречается один раз внутри
  более длинной строки того же символа
- **WHEN** патч применяется без `occurrence`
- **THEN** он применяется успешно (скан непересекающийся, `start += len(find)`)

### Requirement: Одна ограниченная команда для тестового дашборда
Система SHALL предоставлять один вызываемый путь, который поднимает VM,
стейджит фреймворк, собирает дашборд в интерактивной сессии гостя, забирает
`.pbix` на хост, опционально запускает Desktop-оракул и всегда убирает за собой,
завершаясь ровно одним вердиктом.

#### Scenario: Холодный старт
- **GIVEN** VM остановлена, guest-переменные заданы, задан `--vm-uuid`
- **WHEN** выполняется `agentic-bi-guest-dashboard --repo . --oracle`
- **THEN** вердикт `BUILT`, оракул `MODEL_LOADED`, код выхода 0, VM остановлена
  цепочкой (её же и поднявшей)

#### Scenario: Гость не сконфигурирован
- **GIVEN** переменные `AGENTIC_BI_GUEST_*` не заданы
- **WHEN** запускается CLI
- **THEN** вердикт `NOT_CONFIGURED`, код выхода 2, ничего в VM не запускается

#### Scenario: Этап падает по бюджету
- **GIVEN** общий `Deadline` исчерпан на этапе ожидания
- **WHEN** этап проверяет бюджет
- **THEN** возникает `ChainTimeout`, вердикт `TIMEOUT`, задача снята с
  регистрации, хост-серверы закрыты

### Requirement: Стейджинг отдаёт только один файл и проверяет целостность
Хост-сервер передачи файлов SHALL отдавать ровно один файл по одноразовому
токену, SHALL отвечать 404 на любой другой путь и SHALL позволять гостю сверить
SHA-256 переданного файла.

#### Scenario: Запрос чужого пути
- **GIVEN** стейдж-сервер обслуживает файл по пути `/<token>/<name>`
- **WHEN** запрошен `/`, соседний файл каталога или путь без токена
- **THEN** возвращается 404, содержимое каталога не раскрывается

#### Scenario: Передача повреждена
- **GIVEN** хост посчитал SHA-256 исходного файла
- **WHEN** хеш принятого гостём файла не совпадает
- **THEN** возбуждается `StageError`, сборка не продолжается

### Requirement: Экранирование значений в PowerShell
Любое значение, подставляемое в PowerShell-скрипт, SHALL проходить через единый
помощник экранирования (одинарные кавычки с удвоением `'`).

#### Scenario: «Враждебное» значение таблицы
- **GIVEN** таблица задана как `x'; Remove-Item C:\ -Recurse; '`
- **WHEN** формируется скрипт сборки
- **THEN** значение попадает как `'x''; Remove-Item C:\ -Recurse; '''` и не
  порождает вторую инструкцию

#### Scenario: Путь содержит одинарную кавычку
- **GIVEN** имя `.pbix` содержит `'`
- **WHEN** формируется скрипт оракула
- **THEN** путь экранируется и остаётся одним аргументом

### Requirement: Контракт границ CLI и манифеста агента
Консольные точки входа SHALL возвращать документированный код на плохой вход без
стектрейса; манифест агента SHALL отвергать неизвестный `stage`.

#### Scenario: Нечитаемый вход у CLI
- **GIVEN** путь к `.pbix`/`.json` не существует
- **WHEN** запускается соответствующая CLI-команда
- **THEN** выводится понятное сообщение, код возврата документирован (не
  необработанный `FileNotFoundError` со стектрейсом)

#### Scenario: Опечатка в stage манифеста агента
- **GIVEN** манифест агента содержит `stage: "develp"`
- **WHEN** манифест разбирается
- **THEN** возникает `ValueError` (агент не создаётся молча «сиротой»)
